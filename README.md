# Automated Supply Chain & Inventory Performance Analytics

A repeatable, tested pipeline that turns the public **Olist** e-commerce dataset into delivery, supplier and
inventory KPIs: **Python + SQL + PostgreSQL + Prefect + GitHub Actions**, with a **Power BI** report on top.

> **Honesty note.** Olist is real but Brazilian and from 2016–2018. It has no inventory or purchase-order data, so
> those layers are a **seeded simulation driven by real weekly sales** and are labelled *simulated* everywhere
> (`is_simulated` columns, `sim` schema, `(sim)` measures). Delivery findings are real; inventory findings
> demonstrate the method. See [docs/assumptions.md](docs/assumptions.md).

## What it does

```
Kaggle CSVs → raw → staging (+quarantine) → core star schema → marts → Power BI
                         simulate (sim.*) ───────┘            DQ checks gate every stage
                         Prefect daily_refresh @ 06:00 orchestrates it · CI runs tests + the flow on sample data
```

Diagram and run order: [docs/architecture.md](docs/architecture.md).

## Results on the real data

| | |
|---|---|
| Orders processed | 99,435 (6 rejected → quarantine; reconciliation `raw = kept + quarantined` enforced) |
| On-time delivery | **93.2%**; weakest states AL 78.6%, MA 82.6%, SE 84.8% |
| Review score | 4.29 when on time → 2.10 when 4–7 days late |
| DQ | 54 SQL-defined checks (29 raw/staging, 17 core, 8 marts); 2 real-data warnings surfaced |
| Pipeline | 2.5 min end to end; idempotent; 72 automated tests |

Findings and actions: [docs/recommendations.md](docs/recommendations.md) (generated from the marts).

## Quickstart

Requires Docker and Python 3.11+.

```bash
git clone <this repo> && cd supply-chain-analytics
cp .env.example .env                      # set POSTGRES_PASSWORD
python -m venv .venv && .venv/Scripts/activate      # Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"
docker compose up -d postgres             # Postgres 16
python -m sca.download                    # Olist from Kaggle (free token, see src/sca/download.py) → data/raw
python flows/pipeline.py                  # full pipeline: ingest → clean → model → simulate → marts, DQ-gated
python -m sca.dq                          # print the check results
pytest                                    # 72 tests against a throwaway <db>_test database
```

No Kaggle account? Try the pipeline on the committed synthetic sample: `python flows/pipeline.py data/sample`
(use a scratch `POSTGRES_DB`; every run rebuilds all layers).

**Scheduling in Docker:** `docker compose up -d --build` also starts the Prefect server (UI at http://localhost:4200)
and a worker serving `daily_refresh` on cron `0 6 * * *` (container time, UTC). Mount point: `./data` → `/app/data`.

**Dashboard:** open `powerbi/SupplyChain.pbip` in Power BI Desktop ([docs/powerbi.md](docs/powerbi.md)); refresh after a run.

## Layout

| Path | Purpose |
|---|---|
| `src/sca/` | `ingest`, `simulate`, `dq`, `recommend`, `docs`, `make_sample`, db helpers |
| `sql/` | numbered SQL: `10_staging`, `20_core_dims`, `30_core_facts`, `35_core_sim_facts`, `40_marts`, `90_dq` |
| `flows/` | Prefect flow (`pipeline.py`) and scheduler entrypoint (`serve.py`) |
| `tests/` | pytest: cleaning rules, FK/uniqueness, simulation mechanics, KPI recomputation in pandas, DQ failure injection, flow |
| `powerbi/` | `.pbip` project (generated by `build_pbip.py`) and `theme.json` |
| `docs/` | architecture, assumptions, data dictionary, recommendations, build log |
| `data/sample/` | small **synthetic** dataset with deliberately injected dirt, used by CI |

## Quality guarantees

- **Rejects are data:** invalid rows go to `staging.quarantine` with a `reason_code`; nothing is silently dropped.
- **Gates:** a failing *critical* check fails the Prefect run and CI; warnings are reported. Tests prove this by corrupting
  data on purpose (duplicate key, orphan FK, negative price, dropped rejects, lost fact rows).
- **KPIs verified independently:** on-time %, fulfillment, lead-time mean/p90/stddev, turnover and days of supply are
  recomputed in pandas and compared with the SQL views.
- **No secrets in git:** `.env` and Kaggle tokens are ignored.

## Limits

Olist sellers ship directly, so "supplier" = seller and "warehouse" is a modelling device. Results are illustrative,
not current. The Power BI report has no Service-side scheduled refresh (needs Pro); refresh is manual in Desktop.
